# SuperModelingFactory Documentation

This directory holds the **MkDocs site sources** for the [SuperModelingFactory](../SuperModelingFactory/) toolkit. It lives alongside the toolkit repository, at the same level.

## Local Preview

```bash
# 1) Install the documentation dependencies
pip install -r requirements-docs.txt

# 2) Install the SuperModelingFactory runtime dependencies (so mkdocstrings can resolve symbols)
pip install -r ../SuperModelingFactory/requirements.txt

# 3) Start the local preview (default: http://127.0.0.1:8000)
mkdocs serve

# 4) Build the static site into ./site/
mkdocs build --strict
```

## Directory Layout

```
SuperModelingFactory-docs/
├── mkdocs.yml                # Main MkDocs config (theme / navigation / mkdocstrings)
├── requirements-docs.txt     # Documentation site dependencies
├── docs/                     # Documentation source Markdown
│   ├── index.md              # Home page
│   ├── installation.md       # Installation guide
│   ├── quickstart.md         # 5-minute quickstart
│   ├── architecture.md       # Dependency graph and module responsibilities
│   ├── pipeline.md           # End-to-end modeling pipeline
│   ├── guides/               # User guides
│   └── api/                  # API reference (auto-generated by mkdocstrings)
└── overrides/                # Theme customization (reserved)
```

## Content Organization

| Section | Audience | Content |
|---------|----------|---------|
| **Home / Installation / Quickstart** | New users | Project positioning, dependency list, 5-minute example |
| **Architecture / Pipelines** | Intermediate and advanced users | Module dependency graph, typical end-to-end pipelines |
| **User Guides** | Business modelers | Organized by scenario (sample / WOE / feature / model / evaluation / UAT / report) |
| **API Reference** | Tool developers / advanced users | Auto-generated from source docstrings |

## Writing Conventions

- All example code uses relative paths or standard imports, so it can be copied and run as-is
- API heading levels: `<module>.<class>`, `method signature`, `parameters / returns / examples`
- Keep terminology consistent with the main README (binning, WOE plots, scoring, etc.)
- Major changes must also update `pipeline.md` and `quickstart.md`

## Build Output

Running `mkdocs build` generates a complete static site under `site/`, which can be deployed to any HTTP server.
