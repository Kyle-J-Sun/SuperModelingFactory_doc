# v0.8.2

本次发布是一轮集中的缺陷治理：七批修复，覆盖特殊值声明、告警可见性、bool 特征、单一类别数据集评估，以及 SMF 对调用方 DataFrame 的副作用。

!!! warning "与以往 patch 不同：本版在部分路径上会改变结果"
    0.8.1 及之前的 patch 发布承诺"健康输入零数值差异"。**0.8.2 不满足这一条**——它修掉的若干缺陷本身就在产生错误的数字，修好之后数字会变。受影响的是以下三类跑法，升级前请对照复核：

    | 情形 | 影响 |
    |---|---|
    | 声明了**非整数**特殊值（如 `0.5`） | 默认路径打分变化（原先取值 `0` 的普通样本会误拿到 `[sv=0.5]` 的 WOE） |
    | **不带 OOT** 的 FeatureValidationPipeline | 整数特征不再被空占位表退化成 object，相关矩阵/相关过滤/无目标 PSI 恢复工作，**选出的变量可能变** |
    | 调用 `plot_woe` / `plot_woe_group` 后读自己的表 | 你的列名不再被改成小写（见第 7 节） |

    其余修复针对的都是原先直接抛异常的路径，不存在"结果变化"的问题。

## 1. 声明了、但拟合样本里没出现的特殊值

新增 `unseen_special_policy` 参数（`MonotoneWOEBinner` / 一键流水线的 `monotone_woe_params`）：

- `normal_bin`（默认，等同旧行为）：这些取值落进普通箱；
- `neutral`：建一个 WOE=0 的占位箱，`sv_policy_applied="unseen_at_fit"`。

0.9.0 计划把默认翻成 `neutral`。同批修复：

- **非整数特殊值标签的整数截断**：特殊值箱标签会被截断出一个整数键，导致取值 `0` 的普通样本拿到 `[sv=0.5]` 的 WOE。**这条改变默认路径的打分**。
- `CreditModelPipeline` 仅在 WOE 拟合样本里确实出现 `-999999` 时才默认声明它（分箱与打分不变）。
- FVP 按 split 冻结 `unseen_special_stats`（`unseen_special_stats_by_split` / `woe_artifacts["unseen_special_stats_by_target"]`）。

!!! note "已知限制"
    `neutral` 表的 `sv_decisions` 含 `unseen_at_fit`，0.8.1 的加载器会整体拒收（打分不受影响）。`unseen_category_policy="raise"` 对未出现的特殊值只告警不抛错。

## 2. 导入 SMF 不再屏蔽所有告警

`Modeling_Tool.WOE.WOE_Monotone_Binner`（`import Modeling_Tool` 时即加载）与 `Modeling_Tool.Model.Backward_Tool` 在导入时执行了 `warnings.filterwarnings("ignore")`。那是**进程级**的：一旦导入 SMF，SMF 自己的防护告警、你自己代码的告警、第三方库的弃用提示全部消失。两处均已删除，计算结果完全相同，只是这些提示重新可见。

## 3. 清理 SMF 自身调用产生的告警噪音，以及它们掩盖的缺陷

把 SMF 自己触发的弃用与数值告警逐条修掉（seaborn `distplot`/`bw`、WOE/IV 的 `log(0)`、`round`/`pd.cut` 溢出、VIF、lift 的 `0/0`、pandas `concat`/`groupby`/`agg` 的 FutureWarning、sklearn feature names、pyodps `Schema`、shap 全局随机数）。seaborn 迁移复刻了 `distplot` 的 `(mean, 0)` 锚点并画到传入的 axes，12 张含边界情形的图逐像素一致。

修复过程中暴露并修掉的缺陷：

- **FVP 不带 OOT 时整数特征与目标列被空占位表退化成 object**：整数特征被当作类别、没有 IV/KS 的 min/mean/max、被排除出原始值相关矩阵；目标列变 object 后相关过滤对每个特征都失败（`correlated_detail` 始终为空），无目标 PSI 每个特征记一条 TypeError。新增的 `concat_non_empty` 把空帧排除出行拼接。**无 OOT 跑的选变量可能因此改变**，0.8.1 及更早跑过的相关筛选建议重做。
- bool 特征在 FVP 分布摘要中两条路径都丢失（`describe()` 会丢掉与数值列混排的 bool 列），现按类别特征报告。
- 单列表格的 Excel 标题丢失（`merge_range` 拒绝 1×1 区域，静默不写），改为直接写单元格。
- gains 摘要的 `N_BUMP` / `N_BINS` 在缺 split 时不再退化成 object。
- `ModelExplainer.summary_plot` 的散点抖动固定随机种子。

## 4. 单一类别数据集不再让性能评估崩溃

只有好样本（例如没有坏样本的 OOT 窗口）或只有坏样本时，TPR/FPR 全为 NaN，`summarize_roc` 对全 NaN 取 `np.argmax` 得到 -1 并按标签查表，抛 `KeyError(-1)`——`PerformanceEvaluator.evaluate`（普通/加权/基准/分组/多目标）、`evaluate_performance`、`get_perf_summary`、`comparison_performance`、`plot_roc_curve`、`plot_ks_curve` 全部中招，拒绝推断流水线还会因此丢弃每种方法的 evaluator 输出。

现在 KS / AUC 记为 NaN，而 N、坏率、均分、分位目标率与图表照常产出。

## 5. bool 特征不再让分箱、WOE 与流水线崩溃

numpy 不接受对 bool 数组取分位数（`TypeError: numpy boolean subtract`），因此 `quick_binning`、`super_binning`、收益表、`WOE_Master`、`MonotoneWOEBinner.fit`、`feature_screen` 与 `weighted_feature_screen` 碰到 bool 列全部抛错——而同一列 `astype("int8")` 之后一切正常。在开启 WOE 的 FVP 里，它表现为一句被吞掉的"特征洞察计算失败"告警加上 `KeyError: WOE column 'x_woe' was not produced`，整条流程中断。

现在在取分位数的位置把 bool 映射为 0/1（pandas nullable `boolean` 转 `Int8`，缺失值保持缺失）。分箱、WOE 表、IV 与打分结果与同列 int8 副本**逐位一致**；只有 WOE 表的 `MIN` / `MAX` 仍按特征本身报告 `False` / `True`。

## 6. 导入 SMF 不再打开 pandas 的 `future.no_silent_downcasting`

`Core/Binning_Tool.py`、`Core/kDataFrame.py`、`Core/Slope_Tool.py`、`Core/ODPS_Tool.py` 各有一处在导入时打开该全局开关，于是导入 SMF 之后，你自己代码里与 SMF 无关的 `replace()` / `fillna()` 也会改变降级行为并开始报 downcasting 告警。四处全部删除；SMF 自身不依赖它（去掉后全量回归无任何 downcasting 告警）。需要的话请在自己的脚本里显式设置。

## 7. 恢复 pandas 的 `SettingWithCopyWarning`，并修掉九处写回调用方帧的副作用

六处 `pd.options.mode.chained_assignment = None`（`Core/kDataFrame.py`、`Core/Binning_Tool.py`、`Core/ODPS_Tool.py`、`Core/Slope_Tool.py`、`ExcelMaster/Template.py` 在导入时，`Report/Report_Tool.plot_woe` 在调用时）全部删除。它关掉的是 pandas 用来提示"我改了一个切片、改动没生效"这类真实缺陷的告警，而且是进程级的，连你自己的代码也一并失聪。

它当初被关掉，是因为 SMF 自己在 6 个模块的 9 处触发了它。这 9 处已全部改成在自己的帧上操作，因此该告警可以开着而 SMF 全程不响。随之而来的行为变化：

| 位置 | 0.8.1 及之前 | 0.8.2 |
|---|---|---|
| `run_binning` / `super_binning` | 可能把 `bin_num` / `bin_range` 两列写回你传入的 DataFrame | 只出现在返回值里，你的表不动 |
| `get_gains_table`（传 `model` 时） | 在你的表上留下 `_mdl_scr` 临时列 | 不再留下 |
| `plot_woe` / `plot_woe_group`（**公开 API**） | 把你的列名改成小写，并就地替换 `woe` / `iv` 中的 inf | 你的表原样不动，图不变 |
| `scoring` / `select_sample_seed` | 仅触发告警，写入本就落在副本上 | 无变化 |

若你的代码依赖前三行的旧副作用（例如调用 `plot_woe` 之后按小写列名取数），请显式自己做：`df.columns = [c.lower() for c in df.columns]`。
