# v0.7.2

This patch release focuses on the correctness and auditability of the 0.7.1 regression boundaries: it completes governance of categorical small bins at the initial fit stage, tightens the Format-A bins round-trip contract, freezes the categorical transform statistics of every FVP target/split, and gives weighted VIF and constant-weight correlation screening explicit weight semantics. No public API was removed, and no default was flipped.

## Monotone WOE Binning and Format-A Round Trip

- Categorical features now actually execute `small_bin_policy` inside `MonotoneWOEBinner.fit()`: `"merge"` merges using the existing categorical bad-rate clustering logic, `"warn"` keeps the bins and warns, and `"raise"` throws `BinningPolicyViolation`. `"merge"` never pushes the number of ordinary bins below `min_n_bins`; if violating bins remain after reaching the lower limit, `_small_bin_stats[feature]["remaining_violation"]` records that fact. The historical path with `small_bin_policy=None` is unchanged.
- The Format-A DataFrame from `get_final_bins()` now stores the exact numeric boundaries, sparse bin IDs, category members, and per-feature `missing_woe` in `DataFrame.attrs["smf_woe_format_a"]`. `load_woe_bins()` uses this hidden information only after both the metadata digest and the row identity pass validation, so passing the frame directly or round-tripping through pickle restores it exactly.
- Categorical metadata can distinguish bins with identical display text but different members, and preserves hashable tuple categories and category text that looks like a numeric interval. Tampered, stale, non-integer-bin-ID, or non-deep-copyable metadata does not penetrate the loader; instead the whole thing falls back to parsing the visible `bin_label`.
- CSV/Excel do not store `DataFrame.attrs`, so on reload the exported visible labels are the source of truth; the default label still keeps the historical `.8g` display precision. This fallback can restore the visible compressed-interval structure, but cannot restore exact boundaries beyond the text, original sparse bin IDs, ambiguous category members, or a non-default `missing_woe`.
- Numeric transforms continue to use right-closed intervals: a value exactly equal to a cut point goes into the left bin. Categorical transforms count a value as unseen only if both the exact match and the supported `str()` dtype fallback fail; values already resolved by the dtype fallback still leave the fallback warning and coverage statistics, but are no longer reported again as unseen.

## FVP Categorical Transform Audit

- FVP deep-copies `_categorical_transform_stats` and `_unseen_category_stats` immediately after each split transform completes, forming independent `categorical_transform_stats_by_split` / `unseen_category_stats_by_split` under each target. Later split transforms or engine state changes do not overwrite earlier snapshots.
- Lightweight batch results clear the heavy `screening_artifact` and `woe_artifacts["by_target"]` references but keep `woe_artifacts["categorical_transform_stats_by_target"]` and `woe_artifacts["unseen_category_stats_by_target"]`, so batch/slim summaries remain traceable target → split → feature.
- Batch merging deep-merges the statistics by target/split/feature; when the same key has conflicting content, it raises `ValueError` rather than silently letting the later batch overwrite the earlier one.

## Weighted VIF and Correlation Screening

- `FeatureSelectionAnalyzer.compute_vif()` gains an optional `sample_weight`. Non-constant weights use a statsmodels WLS auxiliary regression to compute VIF; when no weights are passed, or constant weights of any normal positive value are passed, the original OLS implementation is still used with strictly identical results. The `drop_rows` mode trims the weights in step, and invalid lengths, non-finite values, negative weights, or a zero total weight continue to fail loudly.
- The G06 VIF gate now passes `weight_col` into the computation above, so non-constant frequency/sample weights can genuinely affect VIF and elimination decisions; the existing IV tie-break semantics are unchanged.
- With `corr_nan_policy="pairwise"`, corr de-duplication under normal positive constant weights directly reuses the unweighted decision path, giving selections identical to the unweighted path while still outputting the weighted screening's `corr_dropped` audit table. The `kept` / `dropped`, pair endpoints, and correlation coefficients in the audit come from the actual iteration decisions.
- `corr_nan_policy="raise"` is not bypassed by the constant-weight fast path. Weighted WOE corr respects the adapter's custom suffix; when some WOE encodings fail, it preserves the full matrix shape, continues to compute the usable numeric sub-matrix, and keeps unencoded features through a warning + NaN rows/columns, avoiding silent mistaken removal.
