# v0.6.4

Release date: 2026-07-15

`0.6.4` rolls up the ODPS descriptive-statistics capability added since `0.6.3` together with two plotting-basis improvements.
This release removes no public API and changes no default of the Pipeline Config.

## New `proc_means_odps()`

A new MaxCompute SQL-pushdown API for descriptive statistics:

```python
from Modeling_Tool import proc_means_odps

summary = proc_means_odps(
    input_table_name="project.wide_table",
    select_cols=["age", "credit_limit", "income"],
    group=["apply_month", "channel"],
    batch_size=50,
)
```

Main capabilities:

- Supports global, single-column, and multi-column group statistics.
- Automatically selects numeric columns from the ODPS schema, and also supports `select_cols` / `skip_cols`.
- Generates aggregation SQL in feature-column batches, downloading only the aggregated result and never pulling the full wide table.
- Supports approximate or exact quantiles, special missing values, and `where_clause` partition filtering.
- Returns a pandas DataFrame by default, with optional CSV output or an explicit write-back to an ODPS table.

## Weighted Evaluation Images and Metrics Unified

Fixes the problem where the weighted branch of `PerformanceEvaluator` computed only the weighted CSV metrics while the images were still drawn from unweighted samples:

- Each dataset independently resolves the `weight_col` it registered.
- The ROC, KDE, Percentile, and Gain panels all use the same sample weights.
- The weighted KDE uses a weighted histogram, per-class KDE, and weighted means.
- The weighted Percentile / Gain curves were completed, and the direction of the Top / Bottom metrics was corrected.

As a result, the INS/OOS/OOT performance images of `CreditModelPipeline` and `perf_results` now use the same basis;
other flows that share `PerformanceEvaluator`, such as RejectInference, benefit as well.

## Clustered By-Group WOE Image Specs

When `MonotoneWOEBinner.plot_woe_graph()` is called under the following condition:

```python
group_name is not None and bar_mode == "clustered"
```

it always uses:

```python
figsize = (16, 6)
dpi = 200
```

The wider canvas fits the side-by-side bars, the by-group WOE curves, and the legend on the right. `pooled`,
`small_multiples`, and plots without a group still use the `figsize` / `dpi` passed in by the caller.
