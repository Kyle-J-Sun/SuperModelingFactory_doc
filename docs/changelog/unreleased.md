# Unreleased

Changes made after 0.8.2 that ship with the next release. The version number is not decided yet.

## 1. All Text Is English

Every docstring, comment, and user-visible string is English, and the four repositories contain no Chinese text. The code is unchanged: the translation touches comments, docstrings, and string contents only.

!!! warning "Code that matches on message text"
    Log, warning, and exception messages, Excel sheet names, and report headings changed language. Scripts that filter logs, use `pytest.raises(match=...)`, or read workbook sheets by name must use the new wording.

| Area | Now |
|---|---|
| Docstrings and comments | English. The [API Reference](../api/index.md) renders the English text |
| Log, warning, and exception messages | English. For example the binner logs `[MonotoneWOEBinner] Fitting 3 features ...`, and the `feature_screen` fallback warning reads `[feature_screen] stage 'psi' eliminated all 40 variables; keeping all of them (on_empty_stage='keep_all_warn')` |
| `MonotoneWOEBinner.export_woe_report` | The sheets are named `WOE Bin Details` and `WOE Bin Charts`, with English headers |
| `Report` templates | English headings, for example *Multi-Model Evaluation (Untuned)*, *Final Model Evaluation*, and *Feature Importance Evaluation* |
| Plot labels | English, for example the axes of `plot_var_reduction` |
| Pipeline GUI schema | `FieldMeta.label`, `description`, and `group`, the registry card text, and the `validate_pipeline_config` messages are English; field names, option values, and defaults are unchanged |

## 2. Fixes Found While Verifying the Documentation

The guides and the docstrings were checked against the installed package, and eleven defects surfaced. Each has a regression test in `test_doc_audit_regressions.py` that fails without the fix.

| Defect | Fix |
|---|---|
| Several `Report.Report_Tool` functions used `pd` and `os` without importing them, so they raised `NameError` when called | The imports are in place |
| The `SampleBalancer` methods `nearmiss`, `tomek`, and `enn` raised `TypeError` with imbalanced-learn 0.14 and later, which dropped `random_state` from those samplers | `random_state` is passed only to samplers that still accept it |
| `get_gains_table`, `get_gains_table_by_cust_metrics`, and `get_perf_summary` iterated over the unfiltered group list after dropping groups below `min_data_size`, so a small group made the next group appear twice and the last one disappear | They iterate over the filtered groups |
| `upload_score`, `h2o_apply_regex`, and `get_dtypes_file(ck_format=True)` raised `NameError`, and the all-missing log call in scoring made `logging` report a formatting error | The helpers import what they use, `ck_format=True` raises `NotImplementedError` with an explanation, and the log call has its placeholder |
| `calibrate` of `LightGBMModel`, `XGBoostModel`, `CatBoostModel`, and `GradientBoostingModel` defaulted to `cv='prefit'`, which scikit-learn 1.8 removed, so every call raised `InvalidParameterError` | The fitted estimator is wrapped in `FrozenEstimator` when it exists; older scikit-learn keeps `cv='prefit'` |
| `BackwardEliminationAnalyzer.get_perf_trend` returned `None` for every value, because it only read dictionary summaries while `BackwardVariableEliminator` stores DataFrames | It reads the stored DataFrames |
| `GradientBoostingModel.param_search` turned integer parameters into floats (`num_leaves=7.0`, which LightGBM rejects), and `refit=True` kept fitting with the pre-search parameters | `best_params_` keeps native types and the model uses the merged parameters |
| `TextEncryptor.decrypt` raised `ValueError` for any text with a non-ASCII character, because `encrypt` stored the plaintext length in characters and `decrypt` compared it with the length in bytes | The length prefix is the byte length. Ciphertexts of ASCII text are unchanged, so existing ones keep decrypting |
| `ExcelFormat.base_filepath` used `str.strip`, which removes characters and not a prefix (`out2/report.xlsx` gave `ut2/`) | It is the directory part of the path, including the trailing separator |
| `compute_overfitting_shift` told the caller that unequal column counts "are the the same" | The message says "are not the same" |
| `ModelExplainer.lime_explain_instance` and `lime_global_importance` raised `AttributeError: 'NoneType' object has no attribute 'copy'` when neither `X_train` nor `background_data` was available, because the intended `ValueError` was checked too late | The check runs first, so the message is `LIME requires X_train or background_data` |

## 3. Complete Docstrings and Parameter Tables

Every public class, function, and method of `Modeling_Tool`, `ExcelMaster`, and `Report` now documents exactly the parameters of its signature, in signature order, in the NumPy layout that the [API Reference](../api/index.md) renders. The Config dataclasses of the Pipelines list every field with its type, default, and behavior, and the parameter tables on the [Top-Level Pipelines](../pipeline_one_click.md) page have a row for every field (34 were missing). The pytest test `test_public_docstring_parameters.py` keeps the docstrings in step with the signatures.

## 4. Further Fixes

Twelve more defects came out of documenting the functions that the first pass had described as they behaved. Each has regression tests in `test_doc_audit_regressions.py` that fail without the fix.

| Defect | Fix |
|---|---|
| `ExcelMaster.add_worksheet(auto_fit=True)` raised `AttributeError`, because it called `worksheet.auto_fit()` and xlsxwriter only has `autofit()` | `close_workbook` fits the columns of those sheets with `autofit()` once the data is written. A column is only widened, never narrowed below the width the sheet already has |
| `write_duo_chart` without `y2_list` raised `TypeError`, because it built the second chart from `None` | Only the first chart is built and inserted. With `retChart=True` the result is `(chart1, None)`, and `write_combined_chart` accepts `chart2=None` |
| `multi_subset_wrapper({})` raised `UnboundLocalError`, because the final `return` used a loop variable of a loop that never ran | It returns an empty DataFrame that has only the column `subset_var_name` |
| `plot_boxplot` and `write_boxplot` multiplied the values by 100 whatever `y_percentage` said, so `y_percentage=False` only dropped the percent labels | `y_percentage=True` multiplies by 100 and formats the axis as percent; `False` draws the values as they are |
| `cross_risk_weighted_mean` kept the weight of a NaN row in the denominator while adding nothing to the numerator, so NaN values pulled the mean towards 0 | A NaN row is skipped. A cell whose values are all NaN is NaN |
| The weighted `get_gains_table` divided the regular bins by the weight of the non-special rows and the special rows by the weight of all rows, so `PROP` added up to more than 1 with `spec_values` | `PROP` is the share of the weight of all rows in every row, so it adds up to 1 |
| `tie_breaker` (feature screening and `lr_elimination_params`) and `iv_equal_freq` were accepted with any value although nothing read them: ties were always broken by ascending feature name (screening) or column order (LR elimination), and the IV binning has no equal-frequency switch, so `tie_breaker="random"` or `iv_equal_freq=False` looked effective. The feature-validation pipeline also took `iv_equal_freq` from `psi_params["equal_freq"]` | Only the value that matches the real behavior is accepted: `tie_breaker` `"name"` (or `None`) for screening and `"pvalue"` (or `None`) for the LR elimination, and `iv_equal_freq=True`. Any other value raises `ValueError` when the config is built (screening) or when `run()` starts (LR elimination). `iv_equal_freq` no longer follows `psi_params["equal_freq"]` |
| `CorrelationFilter(spec_values=...)` stored the special values but never passed them to the `VarExtractionInsights` that computes the IV and KS deciding each correlated group, so on the default path the argument was silently ignored; it worked only with `woe_binner` or `woe_engine="monotone"` | The special values reach the IV and KS calculation on the default path too, in `CorrelationFilter` and in `Feature_Insights.CorrelationFilter`. The default `spec_values=[]` gives the same result as before |
| `ModelExplainer.explain_owen` kept the first SHAP `PartitionExplainer` unless `rebuild=True` or `model_output` changed, so a new `prior_groups`, `coalition_structure`, or `background_data` updated `coalition_structure_` while the Owen values were still computed on the old partition tree (a switch between two groupings gave values that differed from a fresh explainer by up to 0.019 in my check) | The cached explainer is reused only while the coalition structure (features and linkage), the background values, and `model_output` are unchanged; any change rebuilds it. `rebuild=True` still forces a new one |
| `WOE_Master` gave a bin with only goods or only bads a WOE and IV of `-inf` or `+inf`, so a feature with such a bin made LR and XGBoost training fail (`ValueError` and `XGBoostError`) while LightGBM and CatBoost silently took the infinite value. The default `woe_engine="equal_freq"` is affected | Such a bin gets a finite WOE with the `eps` of `MonotoneWOEBinner`: `ln((bad_pct + eps) / (good_pct + eps))` with `eps=1e-06`. Every other WOE and IV value is unchanged, and `calc_woe`, `calc_iv`, and the Gains tables still return infinity for a zero share |
| `CreditModelPipelineConfig.random_state` never reached the LightGBM and XGBoost models, because their built-in parameters fixed `random_state` at 42; the Optuna candidates and the backward-elimination proxy were fixed at 42 too | The built-in LightGBM and XGBoost parameters carry no seed. `random_state` seeds every GBM model the pipeline builds (final models, Optuna candidates, backward proxy), and a `random_state` in `model_params[name]` still wins. The default seed 42 gives the same models as before |
| `CreditModelPipelineConfig.backward_model` ran the XGBoost elimination for every value except the exact lower-case `"lgb"`, so `"LGB"`, `"lr"`, and `"cat"` silently ran XGBoost, and the GUI schema offered `"lr"` and `"cat"` | `run()` accepts `"lgb"` and `"xgb"` in any case and raises `ValueError` for anything else while `backward_enabled` is on. The GUI schema offers only `"lgb"` and `"xgb"`, and `validate_pipeline_config` reports other values |

!!! warning "Results that change"
    A direct call of `plot_boxplot` or `write_boxplot` with the default `y_percentage=False` used to draw the values times 100 and now draws them as they are; the hyperparameter box plots of the reports pass `y_percentage=True` and do not change. `cross_risk_weighted_mean` returns a higher mean for every cell that has NaN values. `PROP` of the weighted `get_gains_table` is smaller in the regular bins when `spec_values` matches rows. A `backward_model` other than `"lgb"` or `"xgb"` now raises `ValueError` when `run()` starts, where it used to run XGBoost; `"LGB"` now runs LightGBM. A credit-model run with a `random_state` other than 42 now trains different LightGBM and XGBoost models (and Optuna candidates and backward proxies) than before; runs with the default seed are unchanged. A feature that has a bin with only goods or only bads now has a finite WOE and IV (it was infinite), so its IV can rank and screen differently; LR and XGBoost models that used to fail now train, LightGBM models on such features change slightly, and CatBoost models are unchanged. Tables with no such bin give identical results. `explain_owen` called again with another `prior_groups`, `coalition_structure`, or `background_data` now returns the Owen values of the new grouping or background; they used to come from the first grouping. Calls with unchanged inputs still reuse the cached explainer. A `CorrelationFilter` called with non-empty `spec_values` now computes its IV and KS with those values in rows of their own, so the IV of a variable whose signal sits in its special values drops and the survivor of a correlated group can change (in my test data the kept variable switched from `a` to `b`); calls with the default `spec_values=[]` are unchanged. A config that sets `iv_equal_freq=False` or a `tie_breaker` other than `"name"` (screening) or `"pvalue"` (LR elimination) now raises `ValueError` where it used to run with no effect; a PSI `equal_freq=False` no longer reaches `iv_equal_freq`, so it keeps working.

## 5. Fixes From the End-to-End Audit of the Two Pipelines

`CreditModelPipeline` and `FeatureValidationPipeline` were run end to end on synthetic data with known properties (a strong feature, a near-duplicate, a constant, a drifting feature, a high-missing feature, special values, weights, an OOT sample), and each stage was compared with an independent recomputation. Each defect below has regression tests in `test_pipeline_e2e_audit.py` that fail without the fix.

| Defect | Fix |
|---|---|
| A constant feature crashed `get_decision_tree_binning_edges` (it returned a tuple instead of a list of edges), so the WOE plots of the screening failed for it. `CreditModelPipeline` swallowed the exception: the whole screening was discarded and every feature, the constant one and the noise included, went on to the models | A feature with one distinct value gets the same list of edges as a tree that makes no split |
| The random INS/OOS split of a frame with a duplicated index (for example after `pd.concat`) duplicated rows and put training rows into OOS: `SampleSplitter.split_df` selected by index label | It selects by position. The partition of a frame with a unique index is unchanged |
| `WOE_Master(missing_ref_value=...)` with a value other than -999999 (for example -99999) fitted the missing rows at -999999 but filled them with `missing_ref_value` when it scored, so they got the WOE of an unrelated bin (-1.32 instead of -0.03 in the test) | `fit` fills with `missing_ref_value` (or `fillna`) too. The default -999999 is unchanged |
| A feature with few distinct values is binned at its own values, so a larger value in new data fell in no bin and got a `NaN` WOE. An LR model then failed, a tree model read it as missing | A value above the last fitted bin (or below the first) takes the WOE of the nearest bin, and the log reports the count |
| The Excel report allocated all 1,048,576 rows of every worksheet: about 0.5 GB and 8 s per sheet, so the 20 sheets of the default `CreditModelPipeline` report needed about 10 GB and were killed by the kernel after everything else had been written | `ExcelMaster.set_cell_size` sets the default row height of the sheet. The layout is the same, a 3-sheet workbook takes 0.1 s and 200 MB instead of 16 s and 1.7 GB |
| Rows with a missing or unknown sample label (`"inss"`, `"train"`) belong to no split, which is documented, but they vanished without a trace | `UserWarning` with the count and the labels, in both pipelines |
| `psi_compare_splits` was case-sensitive and a bare string was exploded into characters, so `["OOT"]` or `"oot"` switched the PSI stage off silently, and a split without rows was skipped silently | Case and spaces are ignored, a bare string is one split, any other name raises `ValueError`, and a requested split without rows gives a `UserWarning` |
| The `psi` column of `feature_selection_summary['psi']` was the INS-vs-OOS value even when the OOT value decided | It is `psi_max`, the value compared with the threshold |
| Every exception of the screening stage of `CreditModelPipeline` became `feature_selection_summary['error']` with all features kept and no warning, and `on_empty_stage='raise'` could never raise. `FeatureValidationPipeline` did not forward `on_empty_stage` | A `RuntimeWarning` announces the failure; `on_empty_stage='raise'` raises `EmptyStageError` (a `ValueError`) through both pipelines |
| `woe_fit_query` was checked on the first 100 rows only: a query that failed on the full data or selected nothing fell back to all rows without a word, and valid expressions that call a method (`x.notna()`, `channel.isin([...])`) were rejected as unknown columns | The query is run on the INS rows when the pipeline starts, a failing or empty query raises `ValueError`, and method calls, string literals and backtick names are read correctly |
| The weighted screening left the missing bin out of the IV, so a feature whose signal is its missingness was dropped with weights of 1.0 and kept without weights | The missing bin counts, as in the unweighted run |
| The weighted correlation dedup was a pairwise greedy pass: the result depended on the column order (a feature was lost because of a partner that a later pair removed), and it ranked by an IV of 0 for every feature when the IV stage was off | Features are processed by descending IV (ties by name) and each one drops the weaker features correlated with it; the IV of the ranking is computed when the IV stage is off |
| `corr_params['method']` and `['base_metric']` of the feature validation only reached the correlation report: a pair that Spearman flags was reported as "remove" and then kept by the selection | `FeatureScreenConfig` has `corr_method` and `corr_base_metric`, and the feature validation sets them from `corr_params`. Weighted runs with non-constant weights support Pearson only and raise `ValueError` otherwise |
| The LR grid search read its best row as one float Series, so an integer parameter such as `max_iter=100` came out as `100.0` and the final fit raised `InvalidParameterError` | Each parameter is read from its own column and keeps its type |
| The default CatBoost parameters carried `random_seed=42` and the pipeline then added `random_state`, which the wrapper turns into `random_seed` and lets win, so a `random_seed` in `model_params['cat']` was silently replaced | The default carries no seed (the config `random_state` supplies 42), and a `random_seed` of the user is kept |
| The backward-elimination proxy took the default LightGBM parameters of the final model: `n_estimators` and `early_stopping_rounds` overrode `num_boost_round` and `early_stopping_rounds` of `backward_params['run']` (300 rounds instead of the documented 200, a patience of 50 instead of 20), the pipeline seed was passed as `random_state` while the preset `seed=42` won, and `eval_weight_col=None` left the validation set weighted with `weight_col`. The XGBoost proxy fitted a squared-error regression to the 0/1 target | The keys that duplicate the run's arguments are dropped, `random_state` becomes the proxy `seed` (a `seed` in `backward_params['run']` still wins), `eval_weight_col=None` gives an unweighted validation set, and the XGBoost proxy uses `binary:logistic` |
| `warm_start_score_type='probability'` clipped log-odds given by mistake to 1e-6 without a word, and the GBMs trained on a constant offset | Values outside [0, 1] raise `ValueError` that names `warm_start_score_type='log_odds'` |
| An `extra_eval_datasets` frame without the evaluation weight column failed with `KeyError` after screening, WOE, searches, training and Optuna; `explain_params` sizes below 1 gave an all-NaN importance table or an `IndexError`; `nrows` in `csv_read_kwargs` raised an obscure `TypeError` | All three are checked when the pipeline starts, with a message that names the setting |
| The target was never validated: a 1/2 coding gave a KS of 600 and an IV of 0, a single-class target an IV of 13 for every feature (noise included), a missing label crashed a model late. A mistyped `target_cols` name switched the WOE, IV/KS, correlation detail and selection stages of `FeatureValidationPipeline` off without a word | Both pipelines raise `ValueError` for labels other than 0/1 and for a single class (`CreditModelPipeline` for missing labels too; `FeatureValidationPipeline` keeps rows with a missing label, as documented), and `FeatureValidationPipeline` warns about `target_cols` names that are not columns |

!!! warning "Results that change"
    A feature screening with `weight_col` now counts the missing bin in the IV, and its correlation stage can keep another feature of a correlated group; screening results with weights therefore differ from before whenever a feature has missing values or a correlated group has three or more members. A `WOE_Master` with a `missing_ref_value` other than -999999 now bins the missing rows at that value. A `woe_fit_query` that failed, or selected no row, now raises where it used to fall back to every INS row. `psi_compare_splits` with a name other than `oos` or `oot` raises. Rows with an unknown sample label are unchanged but now warn. A backward elimination with the default settings now trains 200 rounds with a patience of 20 and the seed `random_state` (it ran 300 rounds, patience 50, seed 42), so the features it keeps can differ; the XGBoost proxy is now a logistic model. A CatBoost model with a `random_seed` in `model_params` now uses it. A target with labels other than 0/1, or with a single class, now raises where it used to run.
