# v0.4.0 Release Notes — MEDIUM Hygiene Batch #2

Release date: 2026-07-06

This release fixes six MEDIUM-severity hygiene bugs in one batch, covering 5 pipeline modules. **M5** is a **behavior change** (it affects calls that relied on an implicit default), so the version becomes 0.4.0 rather than 0.3.19. The other five are purely robustness/performance improvements and are backward compatible.

## Bug Overview

| ID | Module | Type | Scope of impact |
|---|---|---|---|
| M1 | `CreditModelPipeline._run_optuna` | Behavior fix | An empty `search_spaces={}` is now respected |
| M5 | `ScoreComparisonPipelineConfig.cross_vars` | **Default change** | `["rating"]` → `[]` |
| M6 | `ScoreConsistencyUATPipeline._load_dataframes` | Behavior fix | Numeric coercion of object columns is now opt-in |
| M7 | `FeatureValidationPipeline._split_frame` | Observability | bare `except: pass` → warning log |
| M8 | `FeatureValidationPipeline._high_corr_pairs` | Performance | O(n²) Python loop → `np.triu_indices` vectorization |
| M9 | `SampleAnalysisPipeline` | New API | New `dry_run` field + `estimate_split_count()` |

## M1: `optuna_params["search_spaces"]={}` Is Now Respected

**Problem**: `search_spaces = cfg.optuna_params.get("search_spaces") or self._default_search_spaces()`. An empty dict `{}` triggers the `or` short-circuit and falls back to the built-in default search space. A user who explicitly passed an empty one meaning "I don't want to search" got the default search.

**Fix**: an explicit `is None` check.

```python
# After 0.4.0
user_search_spaces = cfg.optuna_params.get("search_spaces")
search_spaces = self._default_search_spaces() if user_search_spaces is None else user_search_spaces
```

**Migration**: none. **To trigger the fallback**, do not set the `search_spaces` key (or pass `None` explicitly).

## M5: `cross_vars` Default Changes from `["rating"]` to `[]` (BREAKING)

**Problem**: `ScoreComparisonPipelineConfig.cross_vars` defaulted to `["rating"]`. In most scenarios there is no `rating` column — `KeyError: Missing required columns: ['rating']` was raised directly in `_validate_input`. Users who wanted a standard score comparison but had no rating column had to explicitly override it to `[]`.

**Fix**:
- The default is now `[]`; when no cross-var is specified, no cross table is produced.
- When something in `cross_vars` is absent from the input data, it now logs `_logger.warning(...)` and skips, instead of raising.
- `_validate_input` no longer counts cross_vars as required columns.

**Migration**:
- If you depend on the `rating` cross: write `cross_vars=["rating"]` **explicitly**.
- If you have no cross requirement: no change needed; you were most likely working around this by passing `cross_vars=[]` by hand, and that is now the default.

## M6: Numeric Coercion of object Columns Is Now Opt-In

**Problem**: `_load_dataframes` iterated over all object columns of `df_compare`, ran `pd.to_numeric(..., errors="coerce")`, and overwrote the whole column as soon as `notna().any()` held. For example, a rating column `["A", "B", "1", "2"]` had A/B silently turned into NaN.

**Fix**: two new config fields:

- `numeric_coercion_mode: str = "safe"`: three modes
  - `"safe"` (default, the new 0.4.0 semantics): convert only when **≥ `numeric_coercion_min_ratio`** (default 99%) of the non-null values can be parsed as numbers; otherwise keep object, and issue a warning when **some** values are parsable, prompting the user to choose explicitly.
  - `"aggressive"`: equivalent to the 0.3.x behavior (convert whenever anything parses), but now **warns on every coercion** with the number of strings lost.
  - `"off"`: skip coercion entirely.
- `numeric_coercion_min_ratio: float = 0.99`: used only in safe mode.

**Migration**: if you depend on the old behavior, set `numeric_coercion_mode="aggressive"`.

## M7: `_split_frame` bare-except Becomes a Warning Log

**Problem**: `FeatureValidationPipeline._split_frame` used `try: SampleSplitter(...).split_df(...) except Exception: pass` to silently fall back to a naive random split. When stratification went wrong, there was no output at all.

**Fix**: `except Exception as exc` + `_logger.warning(...)`, with `target/test_size/random_state/error` details.

**Migration**: none. If debugging was painful before, there is now a log.

## M8: `_high_corr_pairs` Vectorization

**Problem**: with 3000+ features, the original implementation `for i, var1 in enumerate(cols): for var2 in cols[i+1:]: corr_matrix.loc[var1, var2]` made about 4.5 million scalar `.loc[]` lookups, an obvious bottleneck.

**Fix**: `np.triu_indices(n, k=1)` gets the upper-triangle coordinates at once → a `np.abs > threshold` mask filters at once → set membership generates the pair_type. **The numeric output is strictly identical to the old loop version**, verified by the regression test `TestM8HighCorrPairsVectorized::test_matches_loop_reference`.

**Migration**: none. Same result, faster.

## M9: `SampleAnalysisPipeline.dry_run` + `estimate_split_count()`

**Problem**: the default `SampleAnalysisPipelineConfig` of `4 targets × 4 windows × 3 ratios × 20 seeds = 960` `SampleSplitter` calls got started without the user realizing it.

**Fix**:
- New field `dry_run: bool = False`. When enabled, `run()` short-circuits: it skips all expensive computation and returns only `split_candidate_summary=DataFrame([info])` (see info below), with the other DataFrames empty.
- New public method `estimate_split_count(data=None) -> dict`: returns the estimated upper bound on splits; if data is passed, it additionally reports `available_oot_periods` and `windows_usable`.

```python
pipe = SampleAnalysisPipeline(cfg)
pipe.estimate_split_count(df)
# {'n_targets': 4, 'n_oot_windows': 4, 'n_ins_oos_ratios': 3,
#  'n_random_seeds': 20, 'estimated_max_splits': 960,
#  'available_oot_periods': 12, 'windows_usable': 4}
```

**Migration**: none. Off by default. To preview: set `dry_run=True` explicitly or call `estimate_split_count()`.
