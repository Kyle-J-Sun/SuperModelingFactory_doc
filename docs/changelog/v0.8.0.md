# v0.8.0

This minor release introduces **low-share special-value governance (SV Bin Governance)**: two orthogonal switches that govern the WOE estimation of special-value (hereafter SV) bins. In 0.7.2 and earlier, both WOE engines gave every SV an empirical WOE **unconditionally** and counted it toward the total IV, while `min_bin_size` / `small_bin_policy` governed only ordinary interval bins and had no effect on SV bins at all — a `-1` with a 0.05% share and a `NULL` with an 8% share were trusted equally, causing huge variance, an overstated IV, and PSI drift after going live.

The **default combination of the four new parameters is strictly equal to the old behavior**, bit-for-bit identical to 0.7.2; no public API was removed, and no default was flipped.

## New Parameters

| Parameter | Type / default | Values | Semantics |
|---|---|---|---|
| `sv_min_bin_size` | `float = 0.0` | `[0.0, 1.0)` | Threshold on the SV bin's share of the full sample; `0.0` disables it |
| `sv_small_policy` | `str = "keep"` | `keep` / `neutral` / `merge_missing` | Fallback policy for sub-threshold SV bins |
| `sv_woe_smoothing` | `str = "none"` | `none` / `laplace` | Whether to shrink the SV bin's WOE toward the global base rate |
| `sv_smoothing_alpha` | `float = 0.0` | `>= 0.0` | Smoothing strength α; `0.0` disables it |

The four parameters have **the same name, meaning, and basis on both engines**: for `MonotoneWOEBinner.__init__()` they are constructor parameters, and for `WOE_Master.fit()` / `update_woe()` they are method parameters. Illegal values raise `ValueError` at the entry, in the same style as the G08 `small_bin_policy`.

## Mode 1 — Low-Share Fallback

The share is computed as `prop = n_bin / N_total` (**no eps added to the denominator**), and the test is **strictly less than**; a share exactly equal to the threshold does **not** trigger it.

- `keep` (default) takes the empirical WOE, with zero behavior change.
- `neutral` sets the `woe` and `iv` of the sub-threshold SV bin to `0.0`.
- `merge_missing` merges the `bad` / `good` counts of the sub-threshold SV bin into the `[Missing]` bin, and `[Missing]` is then recomputed by the empirical formula; the stored `woe` of the merged row is rewritten to the recomputed `[Missing]` WOE, and `iv` is set to `0` to avoid double-counting in the total IV. When the feature has no `[Missing]` bin, it degrades to `neutral` with a `warnings.warn(UserWarning)`.

It uses a **rewrite-stored-WOE** scheme, so **neither engine's transform path has any change**: `apply_woe()` / `mapping_woe()` look up `bin_label → WOE` as usual and hit the correct value, and the fit→transform round trip is automatically consistent. The actual treatment is written to the `sv_policy_applied` column of the result table (`keep` / `neutral` / `neutral(fallback)` / `merged_into_missing` / `merge_target`).

## Mode 2 — SV WOE Smoothing

`sv_woe_smoothing="laplace"` uses **bad-rate shrinkage**, applied **only** to SV bins, leaving ordinary interval bins untouched:

```
p = N_bad / (N_bad + N_good)
n_bin = n_bad + n_good

r = (n_bad + alpha * p) / (n_bin + alpha)

pct_bad_smoothed  = n_bin * r       / N_bad
pct_good_smoothed = n_bin * (1 - r) / N_good

woe = ln(pct_bad_smoothed / pct_good_smoothed)
```

- `alpha = 0` restores the old empirical WOE bit-for-bit (a regression guardrail).
- As `alpha → ∞`, `r → p`, and the WOE shrinks **monotonically** to `0`.
- α competes with `n_bin`, so **the fewer samples a bin has, the stronger the shrinkage**.

The reason for choosing this form over the "population-denominator pseudo-count" (`(n_bad + alpha*p) / (N_bad + alpha)`) is that the latter converges to `logit(p) ≠ 0` as `alpha → ∞` and is **not monotone**, so increasing the smoothing strength can instead push `|WOE|` higher.

## Orthogonal Combination Semantics

**Mode 1 takes priority**: a sub-threshold bin that goes through the fallback is **not smoothed afterward**; Mode 2 applies only to SV bins that meet the share requirement and keep the empirical WOE. The two switches can be enabled independently or stacked.

When `merge_missing` + `laplace` are both on, the merge target `[Missing]` bin is recomputed by the **empirical** formula (unsmoothed), so that the merged bucket reflects the true post-merge bad rate; other SV bins that meet the share requirement are still smoothed as usual.

The `[Missing]` (NaN) bin is a normal governed SV bin in both engines — smoothed if it meets the requirement, zeroed if it is below the threshold; its only special trait is that under `merge_missing` it can be only a merge target, not a merge source. This capability is orthogonal to `missing_bin_strategy`: the latter governs only the semantics of the NaN missing bin, while the former governs all SV bins (including non-NaN sentinels such as `-1`).

## Pipeline-Layer Exposure

- The two default dicts `woe_params` and `monotone_woe_params` of `CreditModelPipelineConfig` and `FeatureValidationPipelineConfig` now explicitly carry the four `sv_*` keys (values = old behavior), making them first-class parameters that are discoverable, documentable, and snapshot-able, rather than "dict keys that happen to fit".
- The four `sv_*` keys were added to the `FeatureValidationPipeline._MONOTONE_INIT_KEYS` and `Feature_Screen._MONOTONE_INIT_KEYS` allowlists. In these two places, **keys not on the allowlist are silently dropped** (no error, no warning); forgetting to update them would silently disable SV governance in FVP and at screening time, and split the screening IV and the modeling WOE onto different bases. From now on, any new parameter added to `MonotoneWOEBinner.__init__` must be added to both lists.
- The `sv_*` keys are constructor parameters and were **not** added to `_MONOTONE_FIT_KEYS` (`{chi2_binning, chi2_p, chi2_init_size, n_jobs}`); the CM-side monotone fit-only `pop` list likewise stays free of `sv_*`, otherwise they would be passed down as `fit()` kwargs and raise `TypeError`.
- The FVP `config_snapshot` dumps the two dicts verbatim, so `sv_*` automatically enters the snapshot, which makes it easy to reproduce "which SV governance basis a model used".

## Backward Compatibility

- With all-default parameters, the WOE / IV of both engines are **bit-for-bit identical** to the 0.7.2 baseline.
- `laplace` + `alpha=0` is numerically equivalent to the old empirical WOE.
- There is no change on the transform side, and existing mapping tables / Format-A bins artifacts remain usable.
