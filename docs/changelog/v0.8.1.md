# v0.8.1

本次 patch release 修复 `MonotoneWOEBinner` by-group WOE 图上的组 IV 口径，并修复两处加载 / 并行执行的兼容问题。**建模、筛选与 WOE 转换结果与 0.8.0 逐位一致**：变化只出现在 by-group 图上的 IV 数字、开启 SV 治理时 `get_final_bins()` 附带的 attrs，以及原先会报错的代码路径。

## 1. By-group WOE 图的组 IV 改为组内口径

`plot_woe_graph(..., group_name=...)` 三种柱图模式（`pooled` / `clustered` / `small_multiples`）中的各组 IV 在 0.8.0 及之前存在两处缺陷：

- **分母用的是全量样本**：每组各箱的 bad/good 除以整份 `_df_for_group` 的总 bad/good。设该组占全量坏样本比例 s_B、好样本比例 s_G，图上数字约为 s × 组内 IV——k 个规模相近的组各自只显示约 1/k（4 个同质组显示 0.17–0.19，而组内 IV 为 0.69–0.76）；组间坏账率不同时缩小倍数各不相同，无法换算。
- **漏算特殊值 / 缺失箱**：只累加普通箱，而整体图 IV（`vr["iv"]`）包含特殊值箱。

0.8.1 起，组 IV 与整体图 IV 同口径，只是样本换成该组：

- 普通箱：以该组落入普通箱的行的 bad/good 为分母；
- 特殊值箱：以该组全部行的 bad/good 为分母，**沿用拟合时的 `sv_policy_applied` 决策**，不在组内重判占比（`keep` 取经验值、拟合启用平滑时按拟合参数平滑；`neutral` 记 0；`merged_into_missing` 并入该组 `[Missing]`，`[Missing]` 按合并后计数、不平滑）；
- 组内只有单一类别、且未经 laplace 平滑的箱不计入（与筛选 IV 的 `iv_guard` 口径一致）。否则 eps 会把一个空类箱放大成约 0.6 的虚高 IV——坏率 3.6%、每月 5,000 行的月度分组里，有零坏箱的月份曾显示 0.93–0.97（真实约 0.35）。laplace 平滑过的特殊值箱 WOE 有限，照常计入；
- 类别特征中拟合时未出现的取值不计入普通箱分母；样本少于 5 行或单一类别的组仍显示 `IV=0.000`。

未经平滑的拟合箱都两类齐全时，把整份拟合样本当作一个组，组 IV 等于 `vr["iv"]`。

**不变**：各组 **WOE 折线**仍以全量 bad/good 为基准（对两类齐全的箱 = 组内 WOE + 常数 ln(该组 bad 占全量 bad 的比例 / 该组 good 占全量 good 的比例)，便于比较各组坏账水平），柱子、N/TR 标签、文件名、图片尺寸与 dpi 均不变。

## 2. SV 治理决策随 Format-A attrs 往返

开启 SV 治理（`sv_small_policy != "keep"` 或 `sv_woe_smoothing != "none"`）时，`get_final_bins()` 的 `attrs["smf_woe_format_a"]` 新增：

- `sv_decisions`：逐行 `sv_policy_applied`，以及拟合时的平滑方式与 α；
- `sv_decisions_digest`：绑定原有 `metadata_digest` 的独立校验摘要。

`load_woe_bins()` 仅在原有元数据、决策摘要与每个取值都通过校验时恢复决策，使加载后的分箱画出的组 IV 与拟合时一致（即使加载方使用默认 SV 参数）。

- 原有 `metadata_digest` 的计算字段不变：**旧版本加载器仍能验证并精确恢复**边界、箱号与类别成员；
- 未开启 SV 治理的表，attrs 与 0.8.0 完全相同；
- CSV/Excel 回载（attrs 丢失）与格式 B 不带决策，特殊值箱按 `keep` 经验值计；
- 无法可靠往返的 α（NaN、超大整数）不写决策，导出不会失败。

## 3. By-group 图的其他修正

- **拟合箱号不连续**（如 `[0, 2, 3]`）时，各组柱子、折线与数据标签按位置取箱，导致错位且最后一个箱不画；现按真实箱号对齐。
- 两个特殊值渲染成同一标签（如 `special_values=["-999", -999]`）时，特殊值柱子取到空子集而显示为 0；现与组 IV 一致，取第一个非空子集。

## 4. `load_woe_bins` 接受 dict 包装的 Format A 表

`load_woe_bins({feat: {"bin_df": table}})` 因 `payload.get("bin_df") or ...` 对 DataFrame 求真值，总是抛 "The truth value of a DataFrame is ambiguous"。现在 `bin_df` / `df` 两种键都与直接传表等价；包装的值不是 DataFrame 时抛带类型名的 `ValueError`。

## 5. `ParallelApplyEngine` 兼容 joblib ≥ 1.6

joblib 1.6.0（2026-08-31）移除了 `joblib.externals.cloudpickle`，改为依赖独立的 `cloudpickle` 包。此前 `backend="process"` 的可序列化检查把该导入放在改写异常的 `try` 内，**joblib ≥ 1.6 下所有 process 后端调用都会误报** "func, func_args, and func_kwargs must be serializable"。现在优先使用 joblib 内置副本、没有时使用 `cloudpickle` 包；导入问题以 `ImportError` 直接暴露。无新增依赖。

!!! warning "0.8.0 及更早版本 + joblib ≥ 1.6"
    若暂不升级，使用 `ParallelApplyEngine(backend="process")` 前需 pin `joblib<1.6`。
